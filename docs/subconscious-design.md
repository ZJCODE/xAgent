# 潜意识：自主判断与联系偏好记忆

状态：已实现。2026-10-19 完成完整回归及配置模型的真实场景评审。

## 设计原则

潜意识把近期经历、统一日记、关系和已有笔记转化为一次私下思考。内部思考的成本与向外发送的成本不同：有想法可以记下，是否现在联系某个人由 agent 判断。

联系时机结合这个人明确表达的偏好、当前情境、双方关系、内容价值和已有发送记录。时间和未回复是事实，不构成统一的作息规则或发送禁令。一次深夜回复不能直接固化为作息偏好，未收到回复也不能证明拒绝、离线或睡眠。

## 运行与发送链路

1. 心跳维持现有 `subconscious_activity` 概率；无新进展时习惯化衰减，新的经历和独处恢复仍会调节它。
2. 前台正在处理任务或有待处理消息时跳过本轮。前台空闲后可以立即思考，不再读取 `.last_interaction` 决定潜意识是否触发。该文件仍用于日记维护。
3. 开始思考时保存消息游标，组装近期对话、工作摘要、日记、可达联系人的关系卡和笔记。当前时间明确包含运行时的 UTC 偏移，用户所在时区未知时不得猜测。
4. 单次模型推理输出原有四个字段：`internal_content`、`worthy`、`recipient_hint`、`external_content`。联系判断集中在当前任务提示；私下思考模式提示只声明能力和输出约束。
5. `worthy=true` 且有外发内容时，在联系人解析后、调用投递端之前重新检查前台状态和消息游标。思考期间情境已经变化，则本轮只记录内部想法及“我没有发出去”，不排队补发。游标不可读时退化为前台忙闲检查。
6. 成功投递继续记录真实发送历史；失败继续保留诚实的未发送记录。发送后的游标更新维持原有的防自激行为。

以下限制已删除：夜间默认避免主动发送、对话后固定 60 秒不应期、每个联系人最多一条未回复主动消息。`SubconsciousLoop` 不再接受 `refractory_seconds` 和 `max_unanswered_outbound`。

未回复计数仍兼容保存在 `.runtime/subconscious_state.json` 的 `unanswered_outbound` 中，按人物作为临时事实附加到潜意识关系上下文。它不会隐藏联系人或否决发送，也不进入关系卡正文。用户后续发言会清除相应计数。

通道可达性、明确收件人、发送重试和既有通道幂等机制继续有效；日记继续过滤损坏 JSON 和连续相同内容。语音通道保留近期说话检测、每小时主动播报上限、发言权检查与播放互斥。

## 联系偏好的记忆闭环

- 日记是权威载体。日记以第一人称保留“谁向我表达了什么联系偏好、是否临时、后来如何改变”的经历；周期摘要保留仍然重要的偏好与修正。
- 尚未写入日记的新信息由近期对话和工作摘要承接；较新的明确表达可以修正关系卡中的旧印象。
- 日记事务提交成功后，才把本批已提交日记正文、带人物归属的原始经历与旧卡片交给关系卡推导。日记没有新增正文时，不从原始对话单独新增长期结论。
- 关系卡以 agent 自己的第一人称表达对他人的联系偏好，不采用用户自我介绍中的身份。不新增作息表、评分模型或强制结构化用户画像。明确陈述优先于行为推测；临时会议等情境保留适用范围；联系时段偏好不直接证明睡眠或工作作息。
- 关系卡增加可选 `source_diary_dates` 日期列表。更新时合并已有来源与本批真正提交的日记日期，而非投影完成时的日期。旧卡片缺少来源时读为空列表，不补造历史来源。
- 关系卡投影失败不撤销或重放已提交的日记。卡片缺失时仍可根据近期经历和日记进行内部思考。

运行链路不增加每轮模型请求，也不新增延迟发送队列。现有日记维护批次、上下文预算与潜意识 JSON 格式继续使用。

## 验证

自动化回归覆盖：

- 最近刚发生交互也可思考；无回复时联系人仍可见，模型选择的不同后续消息可以发送，计数在重启后继续作为事实存在。
- 思考期间有新消息、前台变忙或队列出现任务时，过时结果留在内部；游标缺失时仍可正常判断忙闲和投递。
- 偏好写入日记后进入关系卡；来源日期往返保存；偏好修正后重新启动仍能读取；群聊中不同人的偏好与发送观察不混淆。
- 没有新增日记时不派生新卡片；投影失败不破坏日记事务和游标。
- 语音通道限制、重试、通道断连处理、工作摘要与日记并发写入保持回归覆盖。

真实模型评审使用 `scripts/subconscious_review.py`，只提供合成经历，投递到临时本地记录，不连接任何消息通道：

```sh
.venv/bin/python scripts/subconscious_review.py --config /path/to/config.yaml --output /tmp/subconscious-review.json
```

固定场景包括夜班、明确勿扰、一次深夜回复、临时会议、未回复但出现新信息、重复想法和人物混淆；同时运行真实日记与关系卡推导及偏好修正。报告保留模型输出与人工评审标准；允许自主判断的场景不强制外发。缺少可用模型配置时应明确报告未执行，不能把离线单元测试描述为真实模型评审通过。

### 本次验证记录（2026-10-19）

- 完整自动化回归：1271 项通过。日记提示最终调整后，日记服务 12 项及关系记忆 40 项定向回归通过。
- 真实模型：使用已有测试配置中的 `deepseek-flash`，运行七组联系场景及真实日记、关系卡推导与偏好修正。所有投递仅进入临时本地存储。
- 夜班且有具体新信息时选择发送；上一条未回复时仍发送新的部署阻塞信息。
- 明确勿扰和临时会议场景保持内部；已发送且无新进展的想法不重复外发；不能联系 Alice 时没有改发给 Bob。
- 单次深夜回复场景没有把观察固化为时区或作息偏好，仍自主选择发送具体的新解题信息。
- 日记与关系卡保持 agent 对他人的叙述；Alice 后续明确改口覆盖旧偏好，Bob 的偏好保留，来源日期对应实际提交日记。

以上是该配置模型在固定合成场景中的行为抽样。脚本保留逐项输出与评审标准，自动检查的成功不能替代对模型内容的审阅。可用 `--scenario memory_correction` 单独复测记忆链路。

## 产品目标核对

- 身份：保持 agent 独立主体与第一人称判断。
- 多用户：按人物与通道归属偏好和投递事实，保持明确收件人及可达性检查。
- 私聊与群聊：保留原始经历中的发言人、房间和情境适用范围。
- 日记视角：偏好作为 agent 的经历记录，观察与推断保持区分。
- 统一记忆：沿用单一日记时间线，不建立按用户隔离的长期记忆库。
- 自主分享：联系时机与未回复后的再次联系交给 agent，代码负责运行与投递协调。
- 日记权威：关系卡是带来源的派生视图，不能成为偏好的唯一载体。
- 归属与连续性：保留来源日期、人物标识、修正和重启后的记忆延续。
