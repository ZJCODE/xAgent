# 潜意识：固定间隔的主动思考

潜意识只负责：到时间在前台空闲时思考一次，可选记下私人笔记，可选给明确联系人发送消息。

## 调度

配置 `agent.subconscious_interval_seconds`，默认 1800 秒，0 表示关闭。心跳每 60 秒检查一次，可通过 `runtime.heartbeat_interval_seconds` 调整；常规思考按潜意识间隔调用，到期跟进可以提前在空闲心跳触发。日记与周期摘要在独立维护任务中执行，不阻塞潜意识检查。

启动时从当前单调时钟安排首次思考；到期但前台忙就等后续心跳，不消耗本次机会。实际开始一次思考时安排下次时间，空结果、模型错误、投递错误均不改变间隔。不补跑错过的轮次，同一进程不会并发执行多个潜意识循环。

旧配置 `subconscious_activity` 仅在配置入口转换：0 转成关闭，正值按心跳间隔除以概率换算固定间隔；新字段优先。初始化模板只生成新字段。旧 `.runtime/subconscious_state.json` 不读取也不删除。习惯化、独处恢复、经历游标和未回复计数均不再参与运行。

## 一次思考

复用近期对话、工作摘要、日记、关系背景和笔记，不提供工具。独立提供一份本轮真实可达联系人名单，标识为 `channel:user_id`。关系卡是可选背景，缺失不影响发送资格。生成和投递使用同一份联系人快照，发送前再检查可达性，不做姓名猜测或模糊匹配。

潜意识与对话、观察和记忆处理共用同一个独立个体视角。想法可以关于自己、一个问题、一个人或多人关系；写私人笔记和对外表达分别决定。涉及人物时保留归属和场景，让笔记离开当前聊天后仍可理解；事实、自己的推测和行动意图保持区分，缺失的人物身份不凭空补认。

关系背景优先读取近期经历中的明确人物，再补充可联系对象，继续使用现有卡片预算。暂时不可联系的人也可以被回想；可达名单仅表示发送地址，不表示这些人都在场或必须联系其中某个人。笔记涉及的人、消息中提到的人和实际收件人可以不同，外发时按实际受众判断披露范围。

思考不等于写日记。每轮先对照近期日记，只保存值得记住的新理解、新观察或意图变化；没有记忆增量时 `note` 为 null。改写旧条目、重复待办或等待状态、解释为什么不发消息、复述本轮能力限制，都不构成新的日记内容。默认结果是 `{"note": null, "decision": {"action": "none"}}`，私人记录与外发仍各自独立。

潜意识不能调用工具只是一轮执行限制，不说明正常对话中没有工具，也不额外建立授权要求。能力和授权判断以相应执行场景的真实信息为准。

模型只输出：

```json
{
  "note": null,
  "decision": {"action": "send", "recipient": "api:Alice", "text": "一条值得分享的新想法"}
}
```

`note` 可为 null，`decision.action` 为 `none` 时不产生外发动作。旧版 `note/message` 协议仍接受。笔记与消息相互独立；消息先交给投递通道，随后写笔记，日记失败不影响投递，投递失败不影响有效笔记保存。代码只接受约定的 JSON 类型，允许外层代码围栏；非法结果记为失败，不把原始输出写入日记。

前台请求入口维护一个进程内版本号，包含新请求和已接受的 steering。思考开始时记录版本，生成完成后若前台忙或版本变化，本轮整体作废。即使插入的短请求已经结束，也能检测到。删除全局消息存储游标检查，尚未投递的暂缓话题保留，下一轮基于新对话重新判断。

投递复用现有通道、历史记录和重试能力；每次重试前检查前台请求，遇到新请求不重发旧内容。已经进入通道的发送遵循该通道的互斥和确认语义。语音通道的潜意识和定时任务共用播放入口，在取得播放锁后检查具体阻止原因；确认播放后才计数和写发送历史，部分播放等不确定结果不自动重试。

## 观察与验证

每轮记录 generation、note、delivery 汇总状态，区分模型失败、请求打断、无消息、无效收件人、不可达、投递成功或失败。具体异常保留日志。投递结果不再自动写成第一人称日记，也不降低后续思考概率。近期真实发送历史供模型判断重复和联系时机。

自动化测试覆盖调度、连续沉默、失败恢复、精确路由、关系卡缺失、前台短请求、重试中断、独立笔记写入、JSON 校验、重启及真实上下文与消息历史。运行：

```sh
.venv/bin/python -m unittest tests.test_subconscious tests.test_agent_config tests.test_runtime_heartbeat -q
.venv/bin/python -m unittest discover -s tests -q
```

真实模型评审脚本使用合成经历和本地投递记录，不连接消息通道：

```sh
.venv/bin/python scripts/subconscious_review.py --config /path/to/config.yaml --output /tmp/subconscious-review.json
```

自动化回归不等于真实模型行为评审。联系偏好继续来自统一记忆，明确边界、重复消息和人物隐私由模型结合上下文判断。

## 暂缓话题与投递回执

潜意识输出的 `decision` 支持 `none`、`send`、`defer`、`close`。暂缓必须给出精确 `recipient`、具体 `subject`、`defer_reason`，以及带时区的未来 `recheck_at` 和更晚的 `expires_at`。已有话题使用运行时提供的 `followup_id`，发送和暂缓不得更换收件人，暂缓不得延长原有过期时间。结束需要 `followup_id` 和 `reason`。

每个 agent 的 `.runtime/followups.sqlite3` 保存话题和逐分片回执，独立于旧心理状态文件。到期话题在空闲心跳唤醒思考，与常规间隔合并调用。已在前台答过的话题由模型关闭，过期话题自动关闭。生成失败、前台插话或未处理的话题最多等待五分钟后复查（配置间隔更短时沿用该间隔）。关闭潜意识也暂停跟进。明确的定点承诺仍由现有定时任务处理。

模型输入明确标注近期记录的来源、实际收件人、自动化输入、私人日记和投递状态。联系偏好以对方明确表述及其时间范围为依据，助手旧日记中的猜测不成为对方的长期指令。私人记录尚未告知对方，未回复的简报也不构成其他话题的全天禁发条件。日记只记录新增理解。

微信主动消息使用稳定 delivery_id，并接入已有任务回执上下文。每个分片的发送意图先落库，确认后记录回执。主动投递上下文关闭适配器内部嵌套重试。已尝试发送却没有确认的结果标为 unknown，进程退出时留下的 sending 同样不自动重放。最近的 accepted/sending/unknown 决定继续提供给模型，以免历史写入失败或重启后把同一内容当成未发。微信业务成功仅表示通道接受，不表示对方已读。

回归运行 `tests.test_subconscious_followups`。真实模型多轮评审运行 `scripts/subconscious_review.py --config /path/to/config.yaml --scenario followup_sequence`，验证夜里暂缓、白天补答，以及前台已答后关闭事项。评审仅使用合成经历和本地模拟投递。
